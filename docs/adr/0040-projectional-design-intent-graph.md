# ADR 0040: Projectional design-intent graph

Status: accepted for M83 implementation. This ADR supersedes the chronological owner-rewrite
design preserved as ADR 0039 on `archive/m83-chronological-lineage-2026-08-23`; that archived
candidate is not product authority and must not be restored wholesale.

## Context

The accepted sketch model is deliberately flat: persistent geometry, constraints, dimensions,
branches and computed-feature intent are compiled into the existing native Rust solver, which is
fast enough for direct manipulation and independently validates every accepted result. That flat
model is an excellent numerical authority, but it does not retain enough semantic ownership to
answer higher-level questions such as “remove this complete Offset”, “edit this rectangle as one
recipe”, or “refer to the same authored result from a GUI, an AI patch and code”.

The first M83 candidate represented editing as a chronological ledger of document snapshots and
rewrote earlier actions by diffing materialized JSON. Human review showed that this joined three
unrelated meanings: dependency, visible row order and Undo history. It also made a drag rewrite an
arbitrary former owner, made display reordering semantically risky, duplicated history, and
required generic JSON leaf ownership. That approach does not provide a credible shared model for
GUI-first prototyping and later code-first formalization.

M83 still may not move constraints into JavaScript, add an expression solver or weaken the native
solver. A code projection and the interactive workbench must edit one canonical meaning while
retaining the existing solver's direct-manipulation performance and accepted-scene authority.

## Decision

### One canonical typed graph, several projections

M83 adds an order-independent, projectional Design Intent Graph. Canvas gestures, schema-generated
Inspector forms, a TypeScript-shaped structured-source view, AI batches and future TypeScript host
bindings all submit the same closed Rust-owned `IntentPatch` vocabulary. None is a privileged
source of truth and none may execute a constraint equation.

The retained session has separately revisioned components:

1. **graph definition** — typed geometry recipes, relations, dimensions, operations, computed
   features, host declarations, explicit branch fields, typed dependencies and stable outputs;
2. **instance state** — writable numerical placement/property leaves keyed by stable output;
3. **organization** — cells, names and display order used only by the Design panel;
4. **external inputs** — exact host parameter and external-snapshot payloads; and
5. **accepted materialization** — the last independently validated native scene plus its complete
   semantic/input stamp and reverse ownership evidence.

Names, aliases, cells, structured-source row order and History order do not affect dependency
scheduling or native allocation. The canonical schedule is the dependency DAG with stable IDs as
the only ready-set tie-break. An unordered patch is canonicalized before planning, uses exact
compare-and-swap input identity and publishes atomically.

### Stable logical identity and native reservations

Every declaration, port, variable-cardinality child and presentation cell has a never-reused
stable identity. Output schemas are generated by Rust from the closed existing M78 recipe and
constraint/dimension/operation catalogs; callers cannot supply arbitrary output manifests.

Logical ports are distinct from persistent native reservations. A port may create a native point,
scalar, curve, contact, constraint, dimension, parameter or external binding; may alias an
existing output; may continue an identity generation; may retire it with a durable typed
tombstone; or may remain logical-only. Constraint/source and dimension/source IDs are reserved as
exact ordered atomic pairs. Suppressed, deleted and failed owners may leave reservations unused,
but high-water still advances so an identity is never recycled.

An existing-point recipe operand aliases the existing point output and allocates no duplicate.
Derived visual handles are logical outputs rather than fabricated persistent sketch points. Child
counts for polylines, splines, patterns and Fillet sets are derived from their typed semantic
operands and validated against fixed limits.

### Deterministic Rust materialization above the unchanged solver

`geosolve-constraint-editor` owns the adapter from the intent graph to the existing public sketch,
feature, operation and retained-session APIs. Materialization:

- decodes exact host inputs;
- allocates the graph's typed native reservations in canonical dependency order;
- lowers only the existing geometry, relation, dimension, operation and computed-Fillet
  vocabulary;
- records stable logical-to-native ownership and writable-free-leaf bindings;
- runs the existing native Rust solver; and
- publishes success only after existing independent residual, finite-geometry, domain and branch
  validation succeeds.

No new residual, constraint type, formula, priority level, weighted hard equation or JavaScript
solve path is introduced. Native Fillet and Profile Offset use their existing authenticated
domain operations rather than a browser reconstruction. Cold reconstruction from canonical
intent and exact inputs is publication authority; a warm materializer may optimize work only when
its result is semantically differential-equal to that cold result.

Invalid explicit intent remains retained and inspectable while the previous independently
accepted materialization stays visible. Cancelled, exhausted or stale work publishes neither
intent nor accepted evidence.

### Direct manipulation edits free instance leaves

At pointer-down the editor prepares one gesture route from the exact accepted materialization and
reverse ownership map. Pointer frames use the existing retained solver session and temporary drag
drivers; they do not serialize/replay the graph, rebuild durable panels or append history. A normal
drag may update only genuinely free writable instance leaves selected by the prepared route. It
must not silently rewrite a driving dimension, fixed target, branch or arbitrary source
declaration.

Fillet radius and Profile Offset distance retain their explicit property gestures. Pointer-up
drains and authenticates the newest sample, performs the exact solve, converts the accepted result
to one instance/property patch and commits one composite history entry. Rejection or cancellation
restores the last accepted scene without a history entry.

### One history, non-semantic History panel

The intent session owns one bounded composite Undo/Redo transaction over graph, instance,
organization and external-input changes together with accepted evidence. The coordinator must not
maintain a second mirrored lineage history. The Design panel's History tab is a read-only audit of
these committed transactions; rearranging Outline or structured-source presentation changes only
organization.

Deleting an operation declaration uses the exact Rust-computed dependent closure and retires its
complete owned output set in one transaction. Undo restores the same semantic identities while
allocator high-water remains monotonic.

### Structured source is a safe projection, not arbitrary execution

Rust generates a deterministic TypeScript-shaped projection using branded stable references and
the closed patch vocabulary. Editing a recognized token or schema field submits a typed patch;
formatting and row movement affect organization only. M83 does not evaluate arbitrary TypeScript,
run user code, permit user-defined constraints or introduce expressions such as
`length = width * 2`.

A DOM-free WASM/RPC surface exposes the same session identity, patch planning, materialization
status, projections and typed failures. A small TypeScript package provides branded handles and
builders over that RPC. It contains no geometry equations or solver fallback.

### Existing workspaces and explicit ejection

Workspace v8 stores the intent session and its exact accepted materialization. Version 7 belongs
to the rejected chronological candidate and is never accepted. Existing v1-v6 flat workspaces and
the current sample library restore through their ordinary strict path, then bootstrap as one
explicit opaque native declaration. That declaration remains fully editable through the existing
flat workbench. The user may explicitly eject/bootstrap supported objects into projectional
declarations; M83 never pretends that arbitrary old geometry was authored by a recipe it cannot
prove.

This is intentionally a breaking experimental workspace boundary. Strict older migrations and
malformed-input rejection remain tested, but compatibility cannot force the rejected ledger back
into the design.

## Consequences

- GUI, AI and code workflows share stable typed references without making source text or row
  chronology semantic.
- The fast native solver remains the sole constraint authority and ordinary dragging remains a
  retained solve rather than graph replay.
- Topological naming is improved for authored results by explicit ports, reservations,
  continuations and tombstones; M83 does not claim to solve arbitrary B-rep naming.
- The materializer is substantial and catalog-driven. Every existing family needs a differential
  golden case, while unsupported projectional editing must fail explicitly or remain inside the
  opaque bootstrap node.
- Workspace v8 is experimental until the M83 human gate passes. GitHub Pages is not updated before
  that approval; the frozen candidate is served over Tailscale.

## Rejected alternatives

- **Chronological snapshot ledger:** conflates dependency, display order and history and relies on
  generic JSON owner rewrites.
- **Arbitrary TypeScript execution:** creates a second, nondeterministic authority and cannot
  participate safely in native interactive solving.
- **JavaScript/formula constraints:** duplicates the solver and violates the no-new-constraint
  scope.
- **Rebuilding the graph on every pointer frame:** defeats the retained solver's interaction
  performance and weakens exact terminal publication.
- **Treating organization order as execution order:** makes harmless UI sorting change geometry.
- **Silently inferring old recipe history:** invents semantic ownership that the flat document
  never recorded.
