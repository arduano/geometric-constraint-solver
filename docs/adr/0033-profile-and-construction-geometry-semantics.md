# ADR 0033: Profile and construction geometry semantics

Status: accepted for implementation in M69; focused qualification and supervising-human UAT are
pending

## Context

M41 added the persistent curve role `GeometryRole::{Profile, Construction}`. Both roles remain
active solver geometry and accept the same constraints and dimensions, while default visual and
production-profile queries exclude Construction. The ordinary workbench already renders a
pre-existing Construction curve with a muted dash, but its headless scene does not carry the role
and every curve competes identically for hover, selection, dragging and authoring picks. Ordinary
drawing also creates only Profile curves, and the UI has no atomic role-conversion action.

ADR 0031 separately makes ordinary Fillets computed features outside the sketch constraint graph.
Successful endpoint claims replace an open native support with one retained source fragment and a
generated arc. The discarded complement is currently absent from output. Treating it as deleted
loses useful construction context; turning it into a new persistent curve would duplicate the
native support, invent topology and make constraints or identity depend on one evaluation.

M69 needs one reusable distinction suitable for a CAD host without freezing the accumulated
draft-v5 sketch state or making the web renderer a second geometry policy owner.

## Decision

### Retain one persistent, curve-scoped role

`GeometryRole::Profile` and `GeometryRole::Construction` remain the only persistent roles.
Construction is not suppression, inactivity or solver exclusion. It stays lowerable,
constrainable, dimensionable and editable, but default profile/topology consumers continue to
exclude it unless their existing explicit construction-inclusive scope is requested.

Points receive no persistent role. A free point participates in ordinary Profile interaction; a
point incident only to visible Construction curves participates in Construction interaction; and
a point shared by both participates in both. This is revision-local incidence metadata rather
than ownership inferred into the document.

Changing several selected curve roles is one validated document transaction and one history step.
Selecting one span of a multi-span curve targets the whole persistent curve. Point, constraint,
dimension and computed-feature selection never implicitly converts incident curves.

Geometry authoring records a requested role in the headless proposal and assigns that role to
every curve it creates before publication. Standalone Point authoring remains role-neutral.
Existing role-unaware public entry points retain Profile as their compatibility default.
Concretely, the editor's typed `CommitConstruction` effect is the authoritative proposal envelope:
it carries the geometry-only `ConstructionProposal` and the role frozen when that draft started.
The retained coordinator applies both in one transaction. Detaching the inner proposal and calling
its compatibility `apply` entry point intentionally means Profile-default authoring, not the M69
role-aware workflow.

Operations that retain a curve identity retain its role. Copy/transform operations inherit the
source role. A new result with several native sources is Construction when any source is
Construction, preventing a construction operand from being silently promoted into a production
profile. Source-free macros use their explicitly requested authoring role and otherwise default to
Profile.

### Publish Fillet-discarded intervals as implicit construction

A successful computed-feature evaluation continues to publish effective source fragments and
generated arcs. Effective edges carry an explicit role: a source fragment inherits its native
curve role, while a Fillet arc is Profile only when all parents are Profile and is Construction
otherwise.

The exact discarded complement of a composed retained interval is published separately as
evaluation-local implicit construction. Each fragment carries its native span source, finite
parameter interval, base interval, responsible Fillet corner and claimed endpoint. It is never
persisted, admitted to the sketch constraint graph or promoted into effective/profile output.
Start and end complements are emitted only when materially non-empty. Failed, suppressed,
conflicting, stale, interrupted or invalid feature output emits no construction ghost. A full
periodic parent remains whole and emits no discarded complement, preserving M68's closed-loop
contract.

The separate collection is a structural safety boundary: downstream consumers cannot mistake
discarded construction for an effective edge merely because both are generated by the same
evaluation. Every fragment remains bounded by the computed-feature work policy and independently
validated for finiteness, containment and non-overlap with the retained interval.

### Resolve implicit fragments through the native source

The headless editor scene distinguishes Profile, explicit Construction and implicit
Fillet-discarded Construction presentation. An implicit fragment is selectable and supplies its
native curve parameter, but its `SelectionItem` is the existing native `CurveSpan`. Selection,
hover, Delete, role conversion, dimensions, constraints and later authoring therefore address the
full native source. The workbench does not create a fragment tree row or fragment edit command.

All rendered occurrences of that native source share selection context. Selecting a discarded
tail highlights both the retained and discarded portions, while their solid/dashed presentation
continues to communicate which portion contributes to effective shape output. Constraint and
problem annotations are deduplicated by the persistent source rather than repeated for every
presentation fragment.

### Make selection scope explicit and headless

The editor owns `All`, `Profile` and `Construction` pick scopes and applies them consistently to
hover, selection, dragging, snapping, ordinary constraint authoring and computed-Fillet
authoring. `All` is the default. The nearest candidate wins unless Profile and Construction hits
differ by no more than one CSS pixel, in which case Profile wins. Within the selected role class,
the existing semantic-kind, distance and persistent-identity ordering remains deterministic.
Authoring operand compatibility is resolved before ordinary point-versus-curve priority.

The workbench may expose visibility independently for explicit and implicit construction, but it
only edits headless scope/session state and renders returned metadata. Visibility and authoring
mode are session-local; persistent curve roles continue to use the existing workspace-v4
canonical-v4/draft-v5 document envelope.

## Scope boundary

M69 does not add persistent point roles, canonical sketch v5, a workspace migration, box
selection, overlap cycling, Offset/Mirror UI, computed-on-computed features, Bake/Explode or
computed production-wire/region consumption. It changes no residual equation, solver priority,
branch policy, independent success validation or activation semantics. Computed-feature output
gains enough explicit role/provenance metadata for a future composed-topology consumer, but M69
does not make `geosolve-sketch-topology` consume it.

## Verification

Direct sketch and operations tests own atomic role editing, authoring, propagation, profile scope
and unchanged mathematical state. Direct computed-feature tests own exact discarded complements,
role propagation, resource bounds and failure withholding. Direct headless-editor tests own role
and incidence DTOs, pick-scope ordering, complete-source identity, compatible authoring and every
interaction path. Thin workbench tests own controls, grouping, styles, accessibility and workspace
round-trip presentation.

The complete native/WASM/release gate and a fresh release Tailscale UAT must pass before M69 can
be marked complete.

## Consequences

- User-authored guides remain ordinary solver geometry without contaminating default profiles.
- Fillet-hidden portions remain inspectable without becoming duplicate persistent geometry.
- A real CAD host can distinguish effective output, explicit guides and derived discarded
  geometry at the Rust interface.
- Exact overlap behavior is deterministic and construction remains intentionally accessible
  through scope controls or the tree.
- Persistence remains unchanged because all new Fillet-hidden geometry is derived.
